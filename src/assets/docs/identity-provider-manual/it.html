Manuale dei provider di identità

Introduzione

I provider di identità consentono l'autenticazione degli utenti tramite servizi di directory esterni come LDAP, Active Directory o OAuth2/OpenID Connect.

Tipi di provider supportati:

  • LDAP - Lightweight Directory Access Protocol standard
  • Active Directory - Microsoft Active Directory
  • OAuth2 - Framework di autorizzazione OAuth 2.0
  • OpenID Connect - Livello di identità su OAuth 2.0

Importazione clienti

Quando "Usa per importazione clienti" è abilitato, vengono importati i seguenti dati:

  • Nome - sn (cognome) o displayName
  • Nome - givenName
  • Titolo - title (titolo professionale)
  • Azienda - company
  • Indirizzo - street/streetAddress, postalCode, l (città), st (stato), c (paese)
  • Genere - Da personalTitle (Sig./Sig.ra) per Active Directory

Nota: Per OpenLDAP, il genere è predefinito "Neutro" e può essere corretto manualmente.

Accesso tramite directory

Se "Usa per autenticazione" è attivato e salvato, le persone possono accedere a Klacks con la password della directory. Nessuno ottiene l'accesso automaticamente: l'amministratore autorizza ogni persona nella scheda Autorizzazione accesso.

  • La scheda elenca gli account della directory (al massimo 1000; con la ricerca si restringe l'elenco).
  • La spunta crea un nuovo account Klacks senza ruolo e senza password. Gli account Klacks esistenti non vengono mai ripresi: se l'indirizzo e-mail è già usato da un account Klacks, la riga non può essere spuntata. Eliminare prima quell'account o cambiarne l'indirizzo e-mail nell'amministrazione utenti.
  • Togliendo la spunta l'account Klacks viene disattivato; spuntando di nuovo viene riattivato, purché non abbia ruoli. Un account disattivato che ha ancora ruoli si riattiva nell'amministrazione utenti.
  • Uscita: quando una persona lascia l'azienda, togliere anche la spunta in Klacks. Bloccare l'account nella directory impedisce nuovi accessi, ma le sessioni già in corso continuano fino alla loro scadenza.
  • Un account senza indirizzo e-mail nella directory non può essere autorizzato.
  • Il proprio account non può essere modificato in questa scheda.
  • Chi ha credenziali della directory corrette ma non è autorizzato riceve il messaggio che l'account non è autorizzato e che deve rivolgersi all'amministratore.

Nomi di accesso

TipoNomi di accesso accettati
Active DirectorysAMAccountName, userPrincipalName o indirizzo e-mail
LDAPuid o indirizzo e-mail

Klacks cerca la persona con l'utente di bind e poi verifica la password presso la directory; il nome di accesso quindi non deve corrispondere all'indirizzo e-mail.

Crittografia

LDAP semplice sulla porta 389 trasmette le password in chiaro; il modulo mostra un avviso per un provider LDAP senza SSL. Se la directory viene usata per l'accesso, utilizzare LDAPS ("Usa SSL", porta 636).

Active Directory: accesso solo tramite LDAPS

Klacks fa accedere le persone ad Active Directory solo tramite LDAPS (porta 636). Senza SSL il modulo mostra un avviso, nessuno può accedere e la scheda Autorizzazione accesso resta chiusa; l'importazione clienti e il test di connessione continuano a funzionare.

  • Host: il nome completo (FQDN) esattamente come compare nel certificato del domain controller, ad es. dc01.example.local. Un indirizzo IP non funziona, perché la verifica del certificato confronta il nome.
  • Fidarsi della CA: il computer su cui gira Klacks deve fidarsi dell'autorità di certificazione che ha emesso il certificato del domain controller. Windows: importare il certificato della CA nell'archivio Autorità di certificazione radice attendibili del computer, ad es. certutil -addstore Root ca.cer (come amministratore).
  • Risoluzione dei nomi: se il FQDN non viene risolto dal DNS, aggiungere una voce nel file hosts (Windows: C:\Windows\System32\drivers\etc\hosts).
  • Docker (non ancora verificato): montare il certificato della CA come file PEM nel container dell'API, impostare la variabile d'ambiente LDAPTLS_CACERT su quel percorso e aggiungere il FQDN con extra_hosts se il DNS non lo risolve.
  • Account di bind: inserirlo come user principal name (UPN), ad es. svc-klacks@example.local.

Quali account vengono importati

  • Gli account disattivati e gli account di sistema di Active Directory non vengono mai importati né elencati.
  • Escludere gli account di servizio con il filtro utente, ad es. solo i membri di un gruppo: (&(objectCategory=person)(objectClass=user)(memberOf=CN=Klacks,OU=Groups,DC=example,DC=local))

Suggerimenti

Synology NAS come server LDAP

Un NAS Synology può essere utilizzato come server LDAP. Installare il pacchetto "LDAP Server" o un container Docker con OpenLDAP.

  • Tipo di provider: "LDAP" (non "Active Directory")
  • Filtro utente: (objectClass=inetOrgPerson)
  • Accesso con uid o indirizzo e-mail
  • Se possibile usare LDAPS (porta 636)

Test connessione

Con il pulsante "Test connessione" si verifica la configurazione. Mostra il numero di account attivi trovati dal filtro utente (gli account disattivati e di sistema non vengono contati) e alcuni nomi utente di esempio. Un "+" dopo il numero significa che il server della directory si è fermato al suo limite di risultati; gli account quindi sono di più.
