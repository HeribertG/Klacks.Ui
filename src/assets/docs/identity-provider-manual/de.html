Identity Provider Handbuch

Einleitung

Identity Provider ermöglichen die Authentifizierung von Benutzern über externe Verzeichnisdienste wie LDAP, Active Directory oder OAuth2/OpenID Connect.

Unterstützte Provider-Typen:

  • LDAP - Standard Lightweight Directory Access Protocol
  • Active Directory - Microsoft Active Directory
  • OAuth2 - OAuth 2.0 Authorization Framework
  • OpenID Connect - Identitätsschicht auf OAuth 2.0

Client-Import

Bei aktiviertem "Für Client-Import verwenden" werden folgende Daten importiert:

  • Name - sn (Nachname) oder displayName
  • Vorname - givenName
  • Titel - title (Jobtitel)
  • Firma - company
  • Adresse - street/streetAddress, postalCode, l (Stadt), st (Kanton), c (Land)
  • Geschlecht - Aus personalTitle (Herr/Frau) bei Active Directory

Hinweis: Bei OpenLDAP ist das Geschlecht standardmässig "Neutral" und kann manuell korrigiert werden.

Anmeldung über das Verzeichnis

Ist "Für Authentifizierung verwenden" aktiviert und gespeichert, können sich Personen mit ihrem Verzeichnis-Passwort bei Klacks anmelden. Niemand erhält automatisch Zugang: Der Administrator gibt jede Person im Reiter Anmelde-Freigabe frei.

  • Der Reiter listet die Verzeichniskonten (höchstens 1000; mit der Suche lässt sich die Liste eingrenzen).
  • Ein Haken legt ein neues Klacks-Konto ohne Rolle und ohne Passwort an. Bestehende Klacks-Konten werden nie übernommen: Wird die E-Mail-Adresse bereits von einem Klacks-Konto verwendet, lässt sich die Zeile nicht anhaken. Löschen Sie dieses Konto zuerst oder ändern Sie dessen E-Mail-Adresse in der Benutzerverwaltung.
  • Wird der Haken entfernt, wird das Klacks-Konto deaktiviert; erneutes Anhaken reaktiviert es, solange es keine Rolle hat. Ein deaktiviertes Konto mit Rollen wird in der Benutzerverwaltung reaktiviert.
  • Austritt: Wenn jemand das Unternehmen verlässt, auch den Haken in Klacks entfernen. Das Sperren im Verzeichnis verhindert neue Anmeldungen, laufende Sitzungen bleiben aber bis zu ihrem Ablauf bestehen.
  • Ein Konto ohne E-Mail-Adresse im Verzeichnis kann nicht freigegeben werden.
  • Das eigene Konto kann in diesem Reiter nicht geändert werden.
  • Wer korrekte Verzeichnis-Anmeldedaten hat, aber nicht freigegeben ist, erhält die Meldung, dass das Konto nicht freigegeben ist und er sich an den Administrator wenden soll.

Anmeldenamen

TypAkzeptierte Anmeldenamen
Active DirectorysAMAccountName, userPrincipalName oder E-Mail-Adresse
LDAPuid oder E-Mail-Adresse

Klacks sucht die Person mit dem Bind-Benutzer und prüft danach das Passwort gegen das Verzeichnis; der Anmeldename muss deshalb nicht der E-Mail-Adresse entsprechen.

Verschlüsselung

Einfaches LDAP auf Port 389 überträgt Passwörter unverschlüsselt; das Formular zeigt bei einem LDAP-Provider ohne SSL eine Warnung. Wird das Verzeichnis für die Anmeldung genutzt, sollte LDAPS ("SSL verwenden", Port 636) eingesetzt werden.

Active Directory: Anmeldung nur über LDAPS

Klacks meldet Personen bei Active Directory nur über LDAPS (Port 636) an. Ohne SSL zeigt das Formular eine Warnung, niemand kann sich anmelden und der Reiter Anmelde-Freigabe bleibt geschlossen; Client-Import und Verbindungstest funktionieren weiterhin.

  • Host: der vollständige Name (FQDN) genau so, wie er im Zertifikat des Domänencontrollers steht, z. B. dc01.example.local. Eine IP-Adresse funktioniert nicht, weil die Zertifikatsprüfung den Namen vergleicht.
  • CA vertrauen: Der Rechner, auf dem Klacks läuft, muss der Zertifizierungsstelle vertrauen, die das Zertifikat des Domänencontrollers ausgestellt hat. Windows: das CA-Zertifikat in den Speicher Vertrauenswürdige Stammzertifizierungsstellen des Computers importieren, z. B. certutil -addstore Root ca.cer (als Administrator).
  • Namensauflösung: Lässt sich der FQDN nicht über DNS auflösen, einen Eintrag in der hosts-Datei anlegen (Windows: C:\Windows\System32\drivers\etc\hosts).
  • Docker (noch nicht verifiziert): das CA-Zertifikat als PEM-Datei in den API-Container einbinden, die Umgebungsvariable LDAPTLS_CACERT auf diesen Pfad setzen und den FQDN mit extra_hosts eintragen, falls DNS ihn nicht auflöst.
  • Bind-Konto: als User Principal Name (UPN) eintragen, z. B. svc-klacks@example.local.

Welche Konten importiert werden

  • Deaktivierte Konten und Systemkonten von Active Directory werden nie importiert und nie aufgelistet.
  • Dienstkonten über den User Filter ausschliessen, z. B. nur Mitglieder einer Gruppe: (&(objectCategory=person)(objectClass=user)(memberOf=CN=Klacks,OU=Groups,DC=example,DC=local))

Tipps

Synology NAS als LDAP-Server

Ein Synology NAS kann als LDAP-Server verwendet werden. Dazu muss das Paket "LDAP Server" oder ein Docker-Container mit OpenLDAP installiert werden.

  • Provider-Typ: "LDAP" (nicht "Active Directory")
  • User Filter: (objectClass=inetOrgPerson)
  • Anmeldung mit uid oder E-Mail-Adresse
  • Wenn möglich LDAPS (Port 636) verwenden

Verbindung testen

Mit "Verbindung testen" lässt sich die Konfiguration prüfen. Angezeigt werden die Anzahl der aktiven Konten, die der User Filter findet (deaktivierte und Systemkonten werden nicht gezählt), und einige Beispiel-Benutzernamen. Ein "+" hinter der Zahl bedeutet, dass der Verzeichnisserver an seinem Ergebnislimit angehalten hat; es gibt also mehr Konten.
