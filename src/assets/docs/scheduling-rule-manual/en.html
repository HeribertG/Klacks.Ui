Scheduling Rules - Explanations

Scheduling rules define the constraints for automatic shift planning. Each rule specifies how working hours, rest periods, and capacities are distributed for a specific group or configuration.

Work Days (Weekdays) & Shift Work

The seven weekdays and shift work have three states. Clicking the box cycles between them: not prescribed, yes, no.

StateBoxMeaning
Not prescribedhorizontal dashThis rule prescribes nothing - the contract decides. This is the normal case.
Yescheck markPrescribed by this rule: work takes place on this day, even if the contract does not provide for it.
NoemptyPrescribed by this rule: no work takes place on this day. This applies to every contract the rule is assigned to - even if the contract explicitly provides for that day.

Note: "No" is an explicit block, not a neutral state. Setting individual days to "yes" does not block the rest: for every day left at "not prescribed", the contract still applies. To exclude a day, you must set it to "no" explicitly.

Shift work works differently: the contract comes first. "Yes" and "no" are this rule's standard for contracts that leave shift work on standard - an explicit value in the contract always takes precedence. "Not prescribed" means the installation default applies unless the contract sets a value. Without shift work, the contract's own surcharge rates (night, holiday, weekend) are ignored and the standard rates apply.

Daily work frame and split shifts

A split shift (e.g. 07:00-11:00 and 16:00-20:00) is one work day: the break between the parts is not a rest period and is not reported as a rest violation, as long as the whole day from the first start to the last end stays within the daily work frame. If a part reaches beyond the frame, a new work day begins, and the short break before it counts as too short a rest.

Which frame applies is set by the law of the place of work. In Switzerland, collective agreements declared generally binding (GAV/LMV) have the force of law. Klacks looks for the value in this order:

  1. Value of this planning rule - e.g. from a collective agreement. An industry package can set it, but only with a verified source; no package ships such a value today.
  2. Company value from the settings (planning rules, default values) - the region package enters the national law here, e.g. Switzerland: 14 hrs (ArG Art. 10 para. 3).
  3. 24 hrs minus the minimum rest - when no frame is set anywhere (e.g. 13 hrs with 11 hrs of rest, EU Directive 2003/88 Art. 3).

Below the field, Klacks shows which value applies and where it comes from. A frame longer than 24 hrs minus the minimum rest only applies to work days within one calendar day: an evening shift and a morning shift on the next day are never merged into one work day.

Remaining rule violations after a wizard run

Wizard 2 and stage 3 (also as steps of the AutoWizard) check hard planning and counter rules with a guard: they make no change that increases how far a person exceeds a hard rule in total. They do not repair existing violations, though, and a violation can shift within the same rule (for example to another day). The first step of the AutoWizard does not plan with these rules yet. A plan can therefore still contain hard violations after the run.

  • Wizard result: after the run, Klacks shows how many hard violations remain. After Wizard 2 and stage 3, Klacks states that no hard rule got worse in total. After the AutoWizard, Klacks gives the count before and after. If there are more than before, Klacks says explicitly that the run added violations.
  • Error list: every hard violation that already existed when the last run started is marked "pre-existing - please check", in the PDF as well. A violation without the marker was not part of the starting state of the last run: it arose later, or it was not shown when the run started (another period or group, or the error list was still loading). The marker applies to the browser session and to the run started last.
  • What to do: planners check the marked entries and correct them by hand. Supervisors and admins can deliberately override a violation when there is a business reason. Admins check whether the rule itself is right.

Usage

Scheduling rules are assigned to a contract. This means the defined limits apply to all employees with that contract during automatic shift planning.

The default values shown here come from the Scheduling Rules (Defaults) in the settings. When creating a new rule, these are automatically applied and can be individually adjusted.
