Setting up WhatsApp

Prerequisites

To send and receive messages via WhatsApp through Klacks, you need a Meta developer account and a Meta App with the WhatsApp product enabled. Klacks uses the WhatsApp Cloud API of the Meta Business Platform for sending and Meta webhooks for receiving.

Note: There are no costs for the setup and for testing. When the app is created, Meta automatically provides a free test phone number.

Important — the sender number is not your private number. A phone number that is already in use in the regular WhatsApp app cannot be registered for the Cloud API, and a registered number can no longer be used with WhatsApp Messenger. Therefore use the test number provided by Meta or your own number used exclusively for business. Your private WhatsApp on your mobile phone serves as the recipient for testing — not as the sender.

Step 1 — Create a Meta App

  1. Open developers.facebook.com/apps and click Create app.
  2. Select Other as the use case and Business as the app type.
  3. In the dashboard, go to the WhatsApp product and click Set up. This automatically creates and registers a test phone number.
  4. In the left-hand navigation, switch to WhatsApp → API Setup.
  5. Note down the Phone number ID and generate an access token via Generate access token.
  6. Under App settings → Basic, note down the App Secret — it is needed to verify the signature of incoming messages.

Caution — two similar IDs: In the API Setup panel, the Phone number ID and the WhatsApp Business Account ID are shown directly below one another. Klacks requires the Phone number ID. With the wrong ID, the connection test still reports success, but every send attempt fails.

Caution — token lifetime: The token generated via Generate access token is a temporary test token and expires after a short time. For permanent operation, generate a permanent token in the Meta Business Manager via a system user.

Step 2 — Authorize the recipient number

The test number may only send to recipients that have been authorized beforehand. In the API Setup panel, add your WhatsApp number under To → Manage phone number list. Meta sends a confirmation code to that number, which you must enter.

Without this step, Meta rejects every message sent to that number. As soon as you later use your own verified business number, this authorization is no longer required.

Step 4 — The 24-hour window

WhatsApp differs fundamentally from Telegram or Slack here. A company may only send free-form text messages while a customer service window is open. This window is opened by the recipient, by writing to your WhatsApp number. It stays open for 24 hours and is extended with every further message from the recipient.

Outside this window, Meta permits only pre-approved message templates. Klacks currently sends only free-form text messages and therefore cannot open a conversation on its own.

What this means for you: Ask your employees to send a message to the Klacks WhatsApp number once. After that, sending is possible for 24 hours, and every reply extends the window. If it is closed, sending reports an error — this is not a configuration problem, but a rule imposed by WhatsApp.

If you need to reach employees independently of this window, Telegram or Signal are the better providers — they do not have this restriction.

Step 5 — Send messages via the chatbot (Klacksy)

Once the WhatsApp provider is configured and enabled, the chatbot Klacksy can send messages via WhatsApp. Use the name of the employee: 

"Send a message to Max Muster: Your appointment is tomorrow at 2 PM."
"Send Anna Beispiel a message: The shift has been swapped."

The recipient is the phone number in international format without a leading zero and without a plus sign (e.g. 41791234567 for 079 123 45 67). The process is fully transparent to you — you work with names, Klacksy takes care of the rest.

Prerequisite: The WhatsApp number must be linked to the corresponding Klacks contact (under Address → Contact Details), and the 24-hour window from Step 4 must be open.

Step 6 — Receive incoming messages (webhooks)

To display incoming WhatsApp messages in Klacks, the webhook of the Meta App must be configured. Save and enable the provider in Klacks before entering the Callback URL — Meta checks the URL immediately with a verification request, which Klacks answers automatically using the Verify Token.

  1. Open your Meta App and navigate to WhatsApp → Configuration.
  2. Next to Webhook, click Edit and enter:
    • Callback URL: the webhook URL shown in Klacks 
      https://{your-domain}/api/messaging/webhook/whatsapp
    • Verify token: exactly the same value that you entered in Step 3 in the Verify Token field
  3. Click Verify and save.
  4. Under Webhook fields, subscribe to the field messages.
  5. Incoming messages will now appear in real time in the Messaging Inbox. Klacks verifies the signature of every request (X-Hub-Signature-256) using the stored App Secret.

The Callback URL must be reachable from the outside via HTTPS. With an installation on a company network without a public address, sending works, but no messages can be received.

Troubleshooting

ProblemPossible CauseSolution
Connection test fails Access token expired Temporary test tokens expire after a short time — generate a new one in the API Setup panel or set up a permanent token
Connection test succeeds, but every send attempt fails Business Account ID entered instead of Phone Number ID Take the Phone number ID from the API Setup panel, not the WhatsApp Business Account ID
Error referring to 24 hours or to re-establishing contact The customer service window is closed The recipient must first send a message to your WhatsApp number — see Step 4
Sending to a specific number fails Recipient not authorized for the test number Add the number under Manage phone number list and confirm it with the code
Webhook verification fails Verify Token does not match or provider not saved/enabled in Klacks Save and enable the provider in Klacks first, then enter the same Verify Token at Meta
Incoming messages missing Webhook field messages not subscribed or App Secret incorrect Subscribe to the field messages under Configuration and check the App Secret
