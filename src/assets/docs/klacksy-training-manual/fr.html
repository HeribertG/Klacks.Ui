Entraînement Klacksy - Manuel

Qu'est-ce que l'outil d'entraînement ?

L'outil d'entraînement contrôle la navigation in-page du chatbot Klacksy. Lorsqu'un utilisateur dit ou écrit "Klacksy montre-moi les adresses", Klacksy navigue vers la page correspondante et fait défiler jusqu'à la section pertinente.

Pour cela, Klacksy a besoin d'une liste de synonymes dans chaque langue pour chaque ancre d'une page (par exemple "adresses", "clients", "contacts" pour la cible addresses).

Onglet "Cibles"

Liste de toutes les ancres trouvées dans le frontend (attribut HTML data-klacksy-target). Filtre de statut :

  • pending : l'ancre existe, pas encore de synonymes
  • generated : synonymes générés automatiquement, à vérifier
  • reviewed : synonymes approuvés par un administrateur
  • needs-review : marqué pour nouvelle vérification

Cliquer sur une cible ouvre l'éditeur de synonymes en dessous. Les synonymes peuvent y être ajoutés, supprimés et validés avec "Enregistrer comme revu".

Onglet "Retours"

Affiche les saisies utilisateur que Klacksy n'a pas pu associer (aucun synonyme correspondant trouvé). Cette liste permet de repérer les synonymes manquants.

Onglet "Métriques"

Vue d'ensemble de toutes les cibles par statut. Aide à suivre l'avancement de l'entraînement.

Pipeline de build (CLI)

Lorsque les templates reçoivent de nouvelles ancres data-klacksy-target, le manifeste et les synonymes initiaux doivent être régénérés. Les commandes suivantes s'exécutent aussi automatiquement en CI et dans le pre-commit Husky : 

cd C:\SourceCode\Klacks.Ui

# 1. Scanner les templates → navigation-targets.json avec toutes les ancres
npm run scan:targets

# 2a. Générer tous les synonymes (4 core + 22 plugin locales, environ 2,5 h)
npm run generate:synonyms

# 2b. Locales core uniquement (de/en/fr/it) — rapide, environ 9 min
npm run generate:synonyms -- --core-only

# 2c. Compléter les locales plugin manquantes — environ 45 min
npm run generate:synonyms -- --plugins-only

# 3. Vérifier la cohérence du wake-word
npm run wake-word-lint

Important : Avec npm run, il faut ajouter -- pour que les options soient transmises au script. Sans cela, npm avale l'option et le script s'exécute en mode par défaut.

Alternative sans npm : npx tsx tools/generate-synonyms.ts --core-only.

Clé d'API

La clé d'API du LLM est résolue dans cet ordre :

  1. Variable d'environnement SYNONYM_LLM_API_KEY
  2. Table DB llm_providers (provider deepseek, is_enabled = true) — automatiquement via un appel psql
  3. Sinon une erreur est levée

Le provider par défaut est DeepSeek. Utilisez un autre provider via SYNONYM_LLM_PROVIDER_ID=anthropic (ou tout autre provider LLM configuré dans les paramètres).

Étape 1 - scan:targets

Parcourt tous les templates Angular à la recherche d'attributs data-klacksy-target et crée le manifeste Application/Skills/Definitions/navigation-targets.json. Chaque nouvelle ancre apparaît ensuite dans l'onglet "Cibles" avec le statut pending.

Étape 2 - generate:synonyms

Génère des synonymes initiaux pour chaque nouvelle ancre à partir du data-klacksy-label-key et de la catégorie. Statut ensuite : generated (doit être validé par un administrateur).

Le script écrit des points de contrôle du manifeste tous les 5 cibles, de sorte qu'une interruption ne perd pas les données déjà générées.

Étape 3 - wake-word-lint

Vérifie la cohérence des variantes du wake-word (Bonjour Klacksy / Hey Klacksy / ...) à travers toutes les langues. Empêche les synonymes de remplacer le wake-word.

Mode vocal

L'icône du microphone dans le chat active le mode vocal. Une fois activé :

  • Le microphone écoute en continu et transcrit
  • Lors d'un court silence → la transcription actuelle est envoyée automatiquement

Important : Dès que vous commencez à taper dans le champ de saisie, le mode vocal est automatiquement désactivé — sinon le microphone écraserait votre texte saisi avec sa transcription et l'enverrait prématurément.

Boucle d'entraînement typique

  1. Ajouter une ancre dans le template : 
    <div data-klacksy-target="addresses"
     data-klacksy-label-key="nav.addresses"
     data-klacksy-route="/workplace/client">
  2. npm run scan:targets && npm run generate:synonyms
  3. Redémarrer l'API (le cache est rechargé au démarrage)
  4. Ouvrir l'onglet "Cibles" → les nouvelles cibles apparaissent avec le statut generated
  5. Vérifier/ajouter les synonymes → "Enregistrer comme revu" → statut reviewed
  6. Tester avec Klacksy, par exemple "Klacksy montre-moi les adresses"
  7. Si Klacksy n'associe pas → onglet "Retours" → ajouter le synonyme manquant
  8. Surveiller l'onglet "Métriques" jusqu'à ce que tout soit reviewed
