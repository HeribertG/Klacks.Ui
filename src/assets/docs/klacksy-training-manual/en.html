Klacksy Training - Manual

What is the training tool?

The training tool controls the in-page navigation of the Klacksy chatbot. When a user says or types "Klacksy show me the addresses", Klacksy navigates to the matching page and scrolls to the relevant section.

For this to work, Klacksy needs a list of synonyms in every language for each anchor on a page (e.g. "addresses", "clients", "contacts" for the target addresses).

Tab "Targets"

List of all anchors found in the frontend (HTML attribute data-klacksy-target). Status filter:

  • pending: anchor exists, no synonyms yet
  • generated: synonyms auto-generated, need review
  • reviewed: synonyms approved by an admin
  • needs-review: flagged for re-review

Clicking a target opens the synonym editor below. Add or remove synonyms there and approve with "Save as reviewed".

Tab "Feedback"

Shows user inputs that Klacksy could not match (no fitting synonym found). Use this list to discover which synonyms are missing.

Tab "Metrics"

Overview of all targets by status. Helps tracking the training progress.

Build pipeline (CLI)

When templates receive new data-klacksy-target anchors, the manifest and initial synonyms must be regenerated. The following commands also run automatically in CI and the Husky pre-commit: 

cd C:\SourceCode\Klacks.Ui

# 1. Scan templates → navigation-targets.json with all anchors
npm run scan:targets

# 2a. Generate initial synonyms (all 4 core + 22 plugin locales, ~2.5 h)
npm run generate:synonyms

# 2b. Core locales only (de/en/fr/it) — fast, about 9 min
npm run generate:synonyms -- --core-only

# 2c. Backfill missing plugin locales — about 45 min
npm run generate:synonyms -- --plugins-only

# 3. Check wake-word consistency
npm run wake-word-lint

Important: With npm run you must include -- so the options are forwarded to the script. Without it, npm swallows the flag and the script runs in default mode.

Alternative without npm: npx tsx tools/generate-synonyms.ts --core-only.

API key

The LLM API key is resolved in this order:

  1. Env variable SYNONYM_LLM_API_KEY
  2. DB table llm_providers (provider deepseek, is_enabled = true) — automatically via psql call
  3. Otherwise an error is raised

Default provider is DeepSeek. Use a different provider via SYNONYM_LLM_PROVIDER_ID=anthropic (or any other configured LLM provider in the settings).

Step 1 - scan:targets

Scans all Angular templates for data-klacksy-target attributes and creates the manifest Application/Skills/Definitions/navigation-targets.json. Each new anchor then appears in the "Targets" tab with status pending.

Step 2 - generate:synonyms

Generates initial synonyms for each new anchor from the data-klacksy-label-key and the category. Status afterwards: generated (must be reviewed by admin).

The script writes manifest checkpoints every 5 targets, so an interrupted run does not lose already generated data.

Step 3 - wake-word-lint

Checks consistency of the wake-word variants (Hello Klacksy / Hey Klacksy / ...) across all languages. Prevents synonyms from overriding the wake-word.

Voice mode

The microphone icon in the chat activates voice mode. Once active:

  • The microphone listens continuously and transcribes
  • On a short silence → the current transcription is auto-sent

Important: As soon as you start typing in the input field, voice mode is automatically disabled — otherwise the microphone would overwrite your typed text with its transcription and send it prematurely.

Typical training loop

  1. Add anchor to template: 
    <div data-klacksy-target="addresses"
     data-klacksy-label-key="nav.addresses"
     data-klacksy-route="/workplace/client">
  2. npm run scan:targets && npm run generate:synonyms
  3. Restart API (cache is re-read on start)
  4. Open "Targets" tab → new targets appear with status generated
  5. Check/add synonyms → "Save as reviewed" → status reviewed
  6. Test with Klacksy, e.g. "Klacksy show me the addresses"
  7. If Klacksy does not match → "Feedback" tab → add missing synonym
  8. Monitor "Metrics" tab until everything is reviewed
