Setting up Signal Messaging

Prerequisites

To send Signal messages through Klacks, you need a self-hosted instance of the signal-cli-rest-api. This is an open-source project that makes Signal accessible through a REST interface.

  • Docker must be installed on the server
  • A phone number registered with Signal (a dedicated number is recommended)
  • The Docker image: bbernhard/signal-cli-rest-api

Important: The Signal integration is designed for sending only. Incoming Signal messages are not received in Klacks.

Step 1 — Set up the signal-cli-rest-api

  1. Start the container with Docker: 
    docker run -d --name signal-cli-rest-api \
  --restart=unless-stopped \
  -p 8080:8080 \
  -v signal-cli-config:/home/.local/share/signal-cli \
  -e MODE=normal \
  bbernhard/signal-cli-rest-api
  2. Link your Signal number using the QR link method: Open in your browser 
    http://localhost:8080/v1/qrcodelink?device_name=klacks
    and scan the displayed QR code with the Signal app on the phone where the number is registered (Settings → Linked Devices → Link New Device). This links the container as a secondary device.
  3. Alternatively, you can register the number independently via the API — see the project documentation for details.
  4. Test the API with a health check: 
    curl http://localhost:8080/v1/about

Note: You can find further configuration details in the signal-cli-rest-api documentation.

Step 2 — Configure Signal in Klacks

  1. Navigate to Settings → Messaging Providers.
  2. Click Add.
  3. Fill in the fields as follows:
FieldDescriptionExample
NameUnique internal namesignal-main
Display NameShown in the user interfaceSignal
Provider TypeSelect SignalSignal
Signal NumberThe registered phone number in international format+41791234567
Signal CLI API URLURL of the signal-cli-rest-api container. If the container runs on the same server as Klacks, this may be http://localhost:8080.http://localhost:8080
EnabledTurns the provider on/offYes
  1. Click Save.
  2. Test the connection using the Test button in the provider list. The test checks whether the given number is registered in the container.

Note: Klacks sends messages via the container's POST /v2/send endpoint.

Step 3 — Send messages via the chatbot (Klacksy)

Once the Signal provider is configured and enabled, the chatbot Klacksy can send messages. You do not need to know any phone numbers — simply use the name of the employee or client: 

"Send a message to Max Muster: Your appointment is tomorrow at 2:00 PM."
"Send Anna Beispiel a Signal message: The shift has been swapped."
"Notify Peter Müller that his shift on Monday is cancelled."

Klacksy automatically looks up the recipient's stored mobile number and uses the configured Signal provider. The process is fully transparent for you — you work with names, Klacksy takes care of the rest.

Prerequisite: The recipient must have a mobile number stored in Klacks (under Address → Contact Details), in international format (e.g. +41791234567). Broadcast messages also fall back to the stored mobile number for Signal delivery.

Incoming Messages

The Signal integration does not support receiving — replies to sent messages are not transmitted to Klacks. The messaging inbox therefore does not show any incoming messages for this provider.

Troubleshooting

ProblemPossible CauseSolution
Connection test fails Container not reachable Check whether the Docker container is running (docker ps) and the API URL is correct
Connection test fails Number not registered in the container Repeat the linking process using the QR link method
Message is not delivered Recipient does not use Signal or number is wrong Make sure the recipient has Signal installed and the number is stored in the format +{country code}{number}
Link lost Device was unlinked in the Signal app Link the container again via the QR link
Container does not start Port 8080 already in use Use a different port: -p 9090:8080 and adjust the API URL in Klacks
