Setting up Signal Messaging

Prerequisites

To send and receive Signal messages through Klacks, you need a running instance of the Signal-CLI REST API. This is an open-source project that makes Signal accessible via a REST interface.

  • Docker must be installed on the server
  • A phone number to be registered with Signal (a dedicated number is recommended)
  • The Docker image: bbernhard/signal-cli-rest-api

Step 1 — Set up the Signal-CLI REST API

  1. Start the Signal-CLI container with Docker: 
    docker run -d --name signal-cli-rest-api \
  --restart=unless-stopped \
  -p 8080:8080 \
  -v signal-cli-config:/home/.local/share/signal-cli \
  -e MODE=normal \
  bbernhard/signal-cli-rest-api
  2. Register your phone number via the API: 
    curl -X POST 'http://localhost:8080/v1/register/{number}' \
  -H 'Content-Type: application/json' \
  -d '{"captcha": "", "use_voice": false}'

    Replace {number} with your number in the format +49171...

  3. Verify the number with the received code: 
    curl -X POST 'http://localhost:8080/v1/register/{number}/verify/{code}'
  4. Test the API with a health check: 
    curl http://localhost:8080/v1/about

Note: For further configuration details, refer to the Signal-CLI REST API documentation.

Step 2 — Configure Signal in Klacks

  1. Navigate to Settings → Messaging Providers.
  2. Click Add.
  3. Fill in the fields as follows:
FieldDescriptionExample
NameUnique internal namesignal-main
Display NameShown in the user interfaceSignal
Provider TypeSelect SignalSignal
Signal NumberThe registered phone number in international format+491711234567
API URLURL of the Signal-CLI REST APIhttp://localhost:8080
EnabledTurns the provider on/offYes
  1. Click Save.
  2. Test the connection using the Test button in the provider list.

Step 3 — Send messages via the chatbot (Klacksy)

Once the Signal provider is configured and enabled, the chatbot Klacksy can send messages. You don't need to know any phone numbers — simply use the name of the employee or client: 

"Send a message to Max Muster: Your appointment is tomorrow at 2 PM."
"Send Anna Beispiel a Signal message: The shift has been swapped."
"Notify Peter Müller that his shift on Monday is cancelled."

Klacksy automatically looks up the recipient's phone number and uses the configured Signal provider. The process is fully transparent to you — you work with names, Klacksy takes care of the rest.

Prerequisite: The recipient must have a mobile number stored in Klacks (under Address → Contact Details).

Step 4 — Receive incoming messages (Webhook)

To display incoming Signal messages in Klacks, a webhook must be configured.

  1. Go to Settings → Messaging Providers.
  2. Note the automatically generated webhook secret of your Signal provider.
  3. Configure the webhook URL in the Signal-CLI REST API: 
    https://{your-domain}/api/messaging/webhook/signal
  4. Incoming messages will now appear in real time in the Messaging Inbox.

Troubleshooting

ProblemPossible CauseSolution
Connection test fails Signal-CLI REST API not reachable Check whether the Docker container is running: docker ps
Message not delivered Signal number not registered or verified Repeat the registration and verification via the API
Recipient does not receive the message Recipient does not use Signal or number is incorrect Make sure the recipient has Signal installed and the number is stored in the format +{country code}{number}
Incoming messages missing Webhook not configured Check the webhook URL in the Signal-CLI REST API configuration
Container does not start Port 8080 already in use Use a different port: -p 9090:8080 and update the API URL in Klacks accordingly
