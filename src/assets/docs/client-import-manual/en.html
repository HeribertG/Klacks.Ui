Employee Import – Manual

What is the employee import?

The employee import takes over a whole staff list from one Excel file (.xlsx) or one CSV file (.csv) with one row per person, instead of creating every person by hand. Klacks recognises the columns itself, shows in a preview how every record will look and only saves after confirmation. Besides employees, the same file can also contain external employees and customers.

  • Who may import: only administrators. The card Import employees is in the settings, section Organization; the button Import opens the import page. Other users do not see the card and need an administrator for the import.
  • Privacy: the file itself is not stored. It is only read; only the rows confirmed in the preview are created.
  • Four steps: File → Mapping & rules → Preview → Result. The tab Manual shows this manual; switching to it does not lose an import in progress.

Supported files

  • Excel (.xlsx) and CSV (.csv); a .txt file is read like a CSV file. The old Excel format .xls is not supported – save the file as .xlsx in Excel first.
  • Excel workbooks: only visible sheets are read, the first one by default. A workbook with several sheets offers the choice Sheet in step 2. The calculated result of a formula is imported. Cells formatted as date are read as dates. Numbers in cells with the format "General" lose leading zeros (postcode 01234 becomes 1234) – format such columns as text (the template already does).
  • Encoding of CSV files: UTF-8 (with or without byte order mark) and UTF-16 with byte order mark are recognised; any other file is read as Windows-1252 (the usual "ANSI" format of Windows Excel in Western Europe), so Western European umlauts and accents come through without any setting. For all other scripts and letters (for example ł, ř, ș, Greek, Arabic, Hebrew, Chinese, Japanese, Korean or Thai), save the file as "CSV UTF-8" or use .xlsx.
  • Delimiter of CSV files: semicolon, comma, tab or vertical bar (|) is detected automatically. Values in quotation marks may contain the delimiter and line breaks.
  • Header row: the first row with column names must lie within the first 10 non-empty rows and contain at least two text cells. Rows above it (for example a title) and empty rows are ignored.
  • Date formats: day, month and year separated by a dot, slash or hyphen, for example 31.12.1990, 12/31/1990 or 1990-12-31; a time part after the date is ignored. A value that starts with a four-digit year is always read as year-month-day. If the file does not show whether the day or the month comes first (no value above 12), Klacks assumes day/month/year and asks for the date format to be checked in step 2. Month names (for example "31 Dec 1990") are not recognised.
  • Two-digit years: years up to the last two digits of the current year count as 20xx, higher ones as 19xx (in 2026: "26" = 2026, "27" = 1927). The preview marks every such date with a warning so the century can be checked.

Limits and larger lists

  • At most 5 MB per file.
  • At most 1000 rows per import – counted are the data rows below the header row, without empty rows.
  • At most 60 columns. In Excel the last used column counts: a single forgotten value far to the right makes the file too wide.
  • A cell may contain at most 1000 characters; longer content is cut off. First name, last name, title and company may have at most 100 characters each, e-mail address, phone and mobile number as well.
  • An Excel file may contain at most 20 MB when unpacked (protection against manipulated files).

Larger lists: split the list into several files of at most 1000 rows each; every file needs its own header row. Columns that are not needed can be deleted beforehand. Import the files one after another. People who were already imported from an earlier file are recognised as duplicates when they have an e-mail address or a date of birth (see Duplicates).

Template

The button Download template in step 1 provides an Excel file in the user's language (file name klacks-employee-import-en.xlsx). With the template every column is recognised reliably. Its header row is bold and frozen, every column is formatted as text (leading zeros and dates stay as typed), and the header of the column Type carries a note with the allowed values. The template has no example row, because it would be imported.

Columns of the template, in this order: First name, Last name, Title, Company, Type, Gender, Date of birth, Street, Address line 2, Postal code, City, State, Country, Email, Phone, Mobile, Start date, End date, Contract, Group, Note. Own lists work as well – Klacks also recognises column names in all 25 Klacks languages and many usual variants (for example "Surname", "ZIP", "Hire date").

Step 1 – File

  • Drag the file onto the upload zone or click the zone to choose a file. Klacks reads the file and moves on to step 2.
  • A file problem (wrong format, too large, too many rows or columns, no header row) is shown directly below the upload zone; see Common errors and fixes.

Step 2 – Mapping & rules

Map columns

  • Every column of the file appears in one line with up to three sample values, the field suggested by Klacks (Import as) and how sure the suggestion is (Confidence).
  • Every suggestion can be changed in the dropdown. A column that should not be imported is set to Do not import. Each field can be assigned to one column only.
  • Date format appears when the file contains dates; when the file does not decide the order of day and month, the selection must be checked.
  • Order in the name field appears for a column with the full name: First name Last name or Last name First name. A comma ("Miller, Anna") always means last name first. The full name only fills a first or last name that has no column of its own or is empty in a row.

Rules for missing information

These rules apply to all rows:

  • Contract if none is given and Group if none is given – used for rows without a contract or group, or with a name that does not exist.
  • Entry date if none is given – empty means today. The date is also the start of the contract, the group assignment and the address.
  • Country if none is given – default Country of the installation.
  • Save email addresses as, Save phone numbers as, Save mobile numbers as – private or business; applies to all rows.
  • Former employees (exit date in the past) – Skip (default) or Import with exit date. An exit date of today or later is always imported.
  • Possible duplicates – Skip (default) or Create anyway.

Continue to preview moves on; Choose another file starts again with a different file.

Step 3 – Preview

  • A summary counts the rows: total, ready, skipped, with errors, duplicates and with warnings. Notes that concern all or many rows appear once above the table, together with the columns that are not imported.
  • The table shows every row as it will be saved, with errors first, then warnings and hints. Show only rows with problems narrows the list.
  • Per row: Skip leaves the row out; Please choose sets the gender of a row without one; Create anyway keeps a row that was recognised as a duplicate.
  • Other values cannot be edited in the preview. To correct them, fix the file and choose it again (Choose another file), or change the mapping with Back.
  • The import button shows how many people will be created (for example Import 25 employees). It stays disabled as long as a row still has an error: fix the row or skip it.

Step 4 – Result

Shows how many people were created and how many rows were skipped, and how many addresses are being located on the map in the background. Go to employee list opens the list, Import another file starts a new import.

Type and company

  • The column Type says per row whether it is an employee, an external employee or a customer. Recognised values are, for example, Employee, Staff, Internal (employee), External, Contractor, Freelancer (external employee) and Customer, Client (customer); the corresponding words of all other Klacks languages and the numbers 0, 1 and 2 work as well. Upper and lower case do not matter.
  • An empty cell or a file without a type column means employee. An unknown value is an error in the preview.
  • Customer with company: created as a company (legal entity), not as a person. First and last name are optional and are kept as the contact person (the preview marks them with Contact person:); a gender in the row is ignored. Such a row needs an address with postcode, city and country (the default country counts).
  • Customer without company: created as a person – first name, last name and gender are required.
  • Employee or external employee with company: stays a person; the company name is stored with the person.
  • Customers never get a contract – neither from the file (warning, the value is not imported) nor from the rules. A group is assigned to customers as well.

Gender and salutation

  • Persons need a gender: Female, Male or Diverse. It comes from the column Gender; if that is empty, from the column Salutation (the preview notes this). Without either, the gender is chosen per row in the preview (Please choose).
  • Recognised values are, for example, Mrs, Ms, Miss, Female, Woman (female), Mr, Male, Man (male) and Diverse, Intersex, Non-binary (diverse) – plus the corresponding words of all other Klacks languages, such as Herr/Frau or Monsieur/Madame.
  • Upper and lower case, accents and punctuation do not matter; for a longer salutation the first word counts ("Mr Dr." = male).
  • A company (customer with company) needs no gender.

Contract and group

  • A value in the file is compared with the names of the existing contracts and groups; upper and lower case and spaces at the beginning or end do not matter.
  • If the name does not exist, exists several times or is empty, the contract or group from the rules is used and the preview says so. Without a rule the row gets no contract or no group.
  • The import does not create contracts or groups. Set them up first in the settings and on the groups page, then import.
  • Contract and group start on the entry date and end on the exit date, if there is one.

Personnel number

Klacks always assigns the personnel number itself. A personnel number column in the file is recognised but ignored; the preview shows a hint. To keep the numbers of another system, the column can be mapped to Note in step 2, as long as no other column is imported as note.

Duplicates

  • Persons: a row counts as a duplicate when the e-mail address is the same, or when first name, last name and date of birth are the same. Upper and lower case, accents and hyphens are ignored ("Müller" = "Muller", "Hans-Peter" = "Hanspeter").
  • Companies (customers with company): same company, postcode and street.
  • Rows are compared with the people already in Klacks and with earlier rows of the same file. Customers are compared only with customers, employees and external employees with each other.
  • Duplicates are skipped with the rule Possible duplicates = Skip. With Create anyway – as a rule for all rows or per row in the preview – they are created anyway.
  • Only a hint, without skipping: the same name without a matching date of birth, or the same company at another address. Check such rows before importing.

Saving and addresses

  • All or nothing: the import saves all ready rows in one go. If anything fails, nothing is saved. Before saving, Klacks checks all rows again against the current data.
  • Created per row: the person (or company), the period of employment from entry to exit date, the address, e-mail address, phone and mobile number, contract, group and note.
  • The same import cannot be saved twice; a second attempt shows that the import has already been carried out.
  • Map: addresses with postcode and city are located on the map in the background after the import, one after another. With many addresses this can take a few minutes; the people can already be used in the meantime.

After the import

  • Imported people are ordinary records. Mistakes are corrected or deleted on the page of the person; there is no "undo" for the whole import.
  • Importing the same file a second time finds rows with an e-mail address or a date of birth again as duplicates. Rows with only a name are merely flagged – check them before importing twice.
  • A single person is created by hand on the employee page; a company directory can be synchronised by an administrator through the identity provider settings.
