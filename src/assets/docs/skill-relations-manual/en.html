Skill Relations – Manual

What are skill relations?

Klacksy observes in the background which skills are frequently used together or in sequence within a session. From this it derives relations – e.g. that create_work almost always follows get_scheduling_defaults. These relations help Klacksy select the right skills more precisely next time.

The learning process runs automatically every 6 hours. This page shows all detected relations and lets admins decide whether to accept or dismiss them.

Relation types

  • Sequential – Skill A is regularly used before Skill B in the same session. Example: search_employees leads to get_client_details.
  • Co-required – Skill A and Skill B are frequently used in the same session without a fixed order. Both are typically needed for the use case.

Source

  • Learned – Calculated from real usage data (PMI / sequence mining). High reliability.
  • Derived – Logically inferred from skill structure, not yet confirmed by usage data.

Status

  • Candidate – Newly detected relation, awaiting admin decision.
  • Active – Accepted relation, actively influences Klacksy.
  • Retired – Dismissed relation, ignored going forward.

Confidence, support, and contradictions

The confidence (0–100 %) indicates how certain Klacksy is about the relation. It rises with each usage session that confirms the pattern (support) and falls with sessions that contradict it (contradictions).

When to accept, when to dismiss?

  • Accept when the relation makes sense – the two skills genuinely belong together and the pattern reflects the desired workflow.
  • Dismiss when the relation is coincidental or the skills do not belong together in this context (e.g. caused by test sessions).

Only learned relations with high confidence are typically worth accepting. Derived candidates with low support are worth dismissing until more usage data is available.
