Setting up KakaoTalk Messaging

Prerequisites

To send messages via KakaoTalk, you need an app on developers.kakao.com (Kakao Developers). KakaoTalk is the dominant messenger in South Korea. The Klacks integration uses the Kakao developer API ("send message to friends").

Important limitations of the Kakao developer API:

  • The integration is designed for sending only — no receiving.
  • The access token is short-lived (approx. 6 hours) and must be renewed outside of Klacks and re-entered.
  • Messages can only be sent to users who are connected as Kakao "friends" of the app and have consented to receiving messages.
  • For production business messaging (AlimTalk), a business channel through authorized agencies is required in Korea — this integration does not cover that; it uses the developer API.

Step 1 — Set up a Kakao Developers app

  1. Create an app on developers.kakao.com.
  2. Enable Kakao Login for the app.
  3. Enable the scopes talk_message and friends.
  4. Obtain an access token via the Kakao Login OAuth flow (the user on whose behalf messages are sent must consent to the scopes).

Note: Treat the access token like a password. Do not share it publicly and store it securely.

Step 2 — Configure KakaoTalk in Klacks

  1. Navigate to Settings → Messaging Providers.
  2. Click Add.
  3. Fill in the fields as follows:
FieldDescriptionExample
NameUnique internal namekakaotalk-main
Display NameShown in the user interfaceKakaoTalk
Provider TypeSelect KakaoTalkKakaoTalk
Access TokenThe token obtained via the OAuth flowkakao-access-token...
EnabledTurns the provider on/offYes
  1. Click Save.
  2. Test the connection using the Test button in the provider list.

Important: The access token expires after approx. 6 hours. Klacks does not renew it automatically — you must renew it externally (Kakao's refresh token flow) and re-enter it in Klacks.

Step 3 — Send messages via the chatbot (Klacksy)

Once the KakaoTalk provider is configured and enabled, the chatbot Klacksy can send messages. You do not need to know any IDs — simply use the name of the employee or client: 

"Send a message to Max Muster: Your appointment is tomorrow at 2:00 PM."
"Send Anna Beispiel a message: The shift has been swapped."
"Notify Peter Müller that his shift on Monday is cancelled."

Klacksy automatically looks up the recipient's stored identifier and uses the configured KakaoTalk provider. The process is fully transparent for you — you work with names, Klacksy takes care of the rest.

Prerequisite: The recipient's friend UUID from the Kakao friends API must be stored in Klacks (under Address → Contact Details). The recipient must be connected as a Kakao "friend" of the app — messages cannot be sent to other users.

Incoming Messages

The KakaoTalk integration does not support receiving — replies to sent messages are not transmitted to Klacks. The messaging inbox therefore does not show any incoming messages for this provider.

Troubleshooting

ProblemPossible CauseSolution
Connection test fails Access token expired (approx. 6 hours validity) Renew the token via the Kakao OAuth flow and re-enter it
Message is not delivered Recipient is not a Kakao "friend" of the app The recipient must connect to the app via Kakao Login and consent to the scope
Recipient not found Friend UUID not stored Determine the UUID via the friends API and enter it under Address → Contact Details
Sending rejected with a permission error Scope talk_message or friends not enabled Check the app's scope settings on developers.kakao.com
Production bulk messaging not possible Developer API does not cover AlimTalk Business messaging in Korea requires a business channel through an authorized agency
