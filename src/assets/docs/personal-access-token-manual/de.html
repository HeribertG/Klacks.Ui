Personal Access Tokens Handbuch

Was sind Personal Access Tokens?

Personal Access Tokens (PATs) sind langlebige API-Schlüssel, die externen Werkzeugen und Diensten einen sicheren Zugriff auf Klacks ermöglichen — ohne Benutzername und Passwort.

Typische Anwendungsfälle:

  • MCP (Model Context Protocol) — erlaubt KI-Assistenten wie Claude Desktop direkten Zugriff auf Klacksy-Skills
  • KI-Agenten und Assistenten, die über MCP mit Klacks arbeiten

Sicherheitskonzept

Klacks speichert niemals das Klartext-Token. Nach der Erstellung wird ausschliesslich ein SHA-256-Hash des Tokens in der Datenbank abgelegt. Das Token selbst wird nur ein einziges Mal direkt nach der Erstellung angezeigt und kann danach nicht mehr abgerufen werden.

Hinweis: Notieren oder kopieren Sie das Token sofort nach der Erstellung. Bei Verlust muss ein neues Token erstellt und das alte widerrufen werden.

Token erstellen

Schritt-für-Schritt

  • Navigieren Sie zu Konfiguration → Personal Access Tokens
  • Klicken Sie auf Neues Token erstellen
  • Vergeben Sie einen aussagekräftigen Namen (z.B. Claude Desktop oder KI-Agent Planung)
  • Wählen Sie die gewünschte Gültigkeitsdauer (1–730 Tage, Standard: 365 Tage)
  • Klicken Sie auf Erstellen
  • Kopieren Sie das angezeigte Token sofort — es wird nur einmalig angezeigt

Token-Format

klacks_pat_<zufällige Zeichenfolge>

Jedes Token beginnt mit dem Präfix klacks_pat_ gefolgt von einer kryptografisch sicheren Zufallszeichenfolge.

Gültigkeitsdauer

DauerEmpfohlener Einsatz
1–30 TageKurzfristige Tests und Entwicklung
90–180 TageKI-Agenten mit regelmässiger Rotation
365 Tage (Standard)Dauerhafte Integrationen (z.B. Claude Desktop)
730 TageLangfristige Systemintegrationen

Zugriffsmodus

Beim Erstellen legen Sie fest, was ein externer Agent mit dem Token tun darf:

  • Nur lesen (Standard) — der Agent sieht und nutzt ausschliesslich lesende Werkzeuge. Jeder Versuch, Daten zu ändern, wird abgelehnt.
  • Lesen und schreiben — der Agent kann zusätzlich Daten ändern, ohne dass ein Mensch die einzelne Änderung noch einmal freigibt. Wählen Sie diesen Modus nur für Agenten, denen Sie Änderungen anvertrauen.

Der Modus wird in der Token-Übersicht angezeigt und lässt sich nachträglich nicht ändern; erstellen Sie bei Bedarf ein neues Token. Bereits vorhandene Tokens und Tokens aus einer OAuth-Anmeldung (z. B. einem MCP-Connector) haben den Modus «Lesen und schreiben».

Token verwenden

Bearer-Token im HTTP-Header

Das Token wird als Bearer-Token im Authorization-Header jeder MCP-Anfrage an den Endpoint /mcp übermittelt:

Authorization: Bearer klacks_pat_...

MCP mit Claude Desktop konfigurieren

Der MCP-Endpoint (/mcp) ermöglicht KI-Assistenten wie Claude Desktop den direkten Zugriff auf alle Klacksy-Skills — Mitarbeiterdaten abfragen, Schichten planen, Gruppen verwalten und vieles mehr.

Konfiguration in der Claude Desktop App (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://<ihre-klacks-domain>/mcp",
        "--header",
        "Authorization:${AUTH_HEADER}"
      ],
      "env": {
        "AUTH_HEADER": "Bearer klacks_pat_..."
      }
    }
  }
}

Ersetzen Sie <ihre-klacks-domain> durch die Adresse Ihrer Klacks-Installation und klacks_pat_... durch Ihr erstelltes Token.

Hinweis: Tokens gelten nur für den MCP-Zugang von KI-Agenten (Endpoint /mcp). Die REST-API von Klacks (z. B. /api/clients) akzeptiert sie nicht; sie verlangt das Login-Token.

Verwaltung und Sicherheit

Übersicht der Tokens

Unter Konfiguration → Personal Access Tokens sehen Sie alle Ihre Tokens mit Name, Erstellungsdatum, Ablaufdatum und letzter Verwendung. Das Klartext-Token wird in dieser Ansicht nie angezeigt.

Token widerrufen

Ein Token kann jederzeit widerrufen werden. Nach dem Widerruf werden alle Anfragen mit diesem Token sofort abgelehnt. Widerrufen Sie Tokens sofort, wenn:

  • Das Token versehentlich weitergegeben wurde
  • Ein Gerät oder Dienst nicht mehr genutzt wird
  • Sie verdächtige Aktivitäten bemerken

Ablauf

Abgelaufene Tokens werden automatisch abgelehnt. Klacks zeigt in der Übersicht Tokens an, die in den nächsten 30 Tagen ablaufen, damit Sie rechtzeitig neue Tokens erstellen können.

Sicherheitstipps

  • Verwenden Sie pro Dienst oder Werkzeug ein separates Token
  • Wählen Sie aussagekräftige Namen, um Tokens eindeutig zuordnen zu können
  • Speichern Sie Tokens niemals im Klartext in Versionsverwaltungssystemen
  • Rotieren Sie Tokens regelmässig
  • Widerrufen Sie Tokens sofort bei Verdacht auf Missbrauch

Jedes Token ist an Ihren Benutzeraccount gebunden. Über MCP gelten die Berechtigungen Ihres Kontos, höchstens jedoch auf Supervisor-Stufe: Auch wenn Ihr Konto Administrator ist, trägt das Token nie Administrator-Rechte. Zusätzlich begrenzt der Zugriffsmodus, was der Agent tun darf: Mit «Nur lesen» nutzt er ausschliesslich lesende Funktionen; mit «Lesen und schreiben» führt er Änderungen ohne weitere Bestätigung aus. Behandeln Sie Tokens mit der gleichen Sorgfalt wie Ihr Passwort.
