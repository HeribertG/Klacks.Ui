Personal Access Tokens Manual

What are Personal Access Tokens?

Personal Access Tokens (PATs) are long-lived API keys that give external tools and services secure access to Klacks — without requiring a username and password.

Typical use cases:

  • MCP (Model Context Protocol) — allows AI assistants like Claude Desktop direct access to Klacksy skills
  • Automation scripts and CI/CD pipelines
  • External monitoring and integration tools

Security concept

Klacks never stores the plaintext token. After creation, only a SHA-256 hash of the token is saved in the database. The token itself is shown only once immediately after creation and cannot be retrieved afterwards.

Note: Copy or save your token immediately after creation. If lost, you must create a new token and revoke the old one.

Creating a Token

Step by step

  • Navigate to Configuration → Personal Access Tokens
  • Click Create new token
  • Enter a descriptive name (e.g. Claude Desktop or CI Pipeline)
  • Select the desired validity period (1–730 days, default: 365 days)
  • Click Create
  • Copy the displayed token immediately — it is shown only once

Token format

klacks_pat_<random string>

Every token starts with the prefix klacks_pat_ followed by a cryptographically secure random string.

Validity periods

DurationRecommended use
1–30 daysShort-term testing and development
90–180 daysCI/CD pipelines with regular rotation
365 days (default)Permanent integrations (e.g. Claude Desktop)
730 daysLong-term system integrations

Using a Token

Bearer token in the HTTP header

The token is transmitted as a bearer token in the Authorization header of every API request:

Authorization: Bearer klacks_pat_...

Configure MCP with Claude Desktop

The MCP endpoint (/mcp) gives AI assistants like Claude Desktop direct access to all Klacksy skills — querying employee data, planning shifts, managing groups, and much more.

Configuration in the Claude Desktop app (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-fetch",
        "https://<your-klacks-domain>/mcp"
      ],
      "env": {
        "AUTHORIZATION": "Bearer klacks_pat_..."
      }
    }
  }
}

Replace <your-klacks-domain> with the address of your Klacks installation and klacks_pat_... with the token you created.

Direct API request (curl)

curl -H "Authorization: Bearer klacks_pat_..." \
     https://<your-klacks-domain>/api/clients

Management and Security

Token overview

Under Configuration → Personal Access Tokens you can see all your tokens with their name, creation date, expiry date, and last use. The plaintext token is never shown in this view.

Revoking a token

A token can be revoked at any time. After revocation, all requests using that token are immediately rejected. Revoke a token immediately when:

  • The token was accidentally shared or exposed
  • A device or service is no longer in use
  • You notice suspicious activity

Expiry

Expired tokens are automatically rejected. Klacks highlights tokens expiring within the next 30 days in the overview so you can create replacements in time.

Security tips

  • Use a separate token for each service or tool
  • Choose descriptive names so tokens can be clearly identified
  • Never store tokens in plaintext in version control systems
  • Rotate tokens regularly, especially when used in CI/CD
  • Revoke tokens immediately if you suspect misuse

Each token is bound to your user account and carries the same permissions as your account. Treat tokens with the same care as your password.
