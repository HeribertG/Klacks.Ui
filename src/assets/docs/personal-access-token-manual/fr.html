Manuel des jetons d'accès personnels

Que sont les jetons d'accès personnels ?

Les jetons d'accès personnels (PAT) sont des clés d'API durables qui permettent aux outils et services externes d'accéder à Klacks de manière sécurisée — sans nom d'utilisateur ni mot de passe.

Cas d'utilisation typiques :

  • MCP (Model Context Protocol) — permet aux assistants IA comme Claude Desktop d'accéder directement aux compétences Klacksy
  • Agents et assistants IA qui travaillent avec Klacks via MCP

Concept de sécurité

Klacks ne stocke jamais le jeton en clair. Après la création, seul un hachage SHA-256 du jeton est enregistré dans la base de données. Le jeton lui-même n'est affiché qu'une seule fois, immédiatement après sa création, et ne peut pas être récupéré ultérieurement.

Remarque : copiez ou notez votre jeton immédiatement après sa création. En cas de perte, vous devez créer un nouveau jeton et révoquer l'ancien.

Créer un jeton

Étape par étape

  • Accédez à Configuration → Jetons d'accès personnels
  • Cliquez sur Créer un jeton
  • Saisissez un nom explicite (p. ex. Claude Desktop ou Agent IA planification)
  • Sélectionnez la durée de validité souhaitée (1–730 jours, par défaut : 365 jours)
  • Cliquez sur Créer
  • Copiez immédiatement le jeton affiché — il n'est visible qu'une seule fois

Format du jeton

klacks_pat_<chaîne aléatoire>

Chaque jeton commence par le préfixe klacks_pat_ suivi d'une chaîne aléatoire cryptographiquement sécurisée.

Durées de validité

DuréeUtilisation recommandée
1–30 joursTests à court terme et développement
90–180 joursAgents IA avec rotation régulière
365 jours (par défaut)Intégrations permanentes (p. ex. Claude Desktop)
730 joursIntégrations système à long terme

Mode d’accès

Lors de la création, vous définissez ce qu’un agent externe peut faire avec le jeton :

  • Lecture seule (par défaut) — l’agent voit et utilise exclusivement des outils de lecture. Toute tentative de modifier des données est refusée.
  • Lecture et écriture — l’agent peut en plus modifier des données sans qu’une personne valide chaque modification. Ne choisissez ce mode que pour des agents auxquels vous confiez des modifications.

Le mode est affiché dans la liste des jetons et ne peut pas être modifié ultérieurement ; créez un nouveau jeton si nécessaire. Les jetons existants et ceux émis via une connexion OAuth (p. ex. un connecteur MCP) ont le mode « Lecture et écriture ».

Utiliser un jeton

Jeton Bearer dans l'en-tête HTTP

Le jeton est transmis en tant que jeton Bearer dans l'en-tête Authorization de chaque requête MCP vers le point de terminaison /mcp :

Authorization: Bearer klacks_pat_...

Configurer MCP avec Claude Desktop

Le point de terminaison MCP (/mcp) donne aux assistants IA comme Claude Desktop un accès direct à toutes les compétences Klacksy — consulter les données des employés, planifier des équipes, gérer des groupes et bien plus encore.

Configuration dans l'application Claude Desktop (claude_desktop_config.json) :

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://<votre-domaine-klacks>/mcp",
        "--header",
        "Authorization:${AUTH_HEADER}"
      ],
      "env": {
        "AUTH_HEADER": "Bearer klacks_pat_..."
      }
    }
  }
}

Remplacez <votre-domaine-klacks> par l'adresse de votre installation Klacks et klacks_pat_... par le jeton que vous avez créé.

Remarque : Les jetons ne fonctionnent que pour l'accès MCP des agents IA (point de terminaison /mcp). L'API REST de Klacks (p. ex. /api/clients) ne les accepte pas ; elle exige le jeton de connexion.

Gestion et sécurité

Vue d'ensemble des jetons

Sous Configuration → Jetons d'accès personnels, vous pouvez voir tous vos jetons avec leur nom, date de création, date d'expiration et dernière utilisation. Le jeton en clair n'est jamais affiché dans cette vue.

Révoquer un jeton

Un jeton peut être révoqué à tout moment. Après révocation, toutes les requêtes utilisant ce jeton sont immédiatement rejetées. Révoquez un jeton immédiatement lorsque :

  • Le jeton a été accidentellement partagé ou exposé
  • Un appareil ou service n'est plus utilisé
  • Vous remarquez une activité suspecte

Expiration

Les jetons expirés sont automatiquement rejetés. Klacks met en évidence dans la vue d'ensemble les jetons qui expirent dans les 30 prochains jours afin que vous puissiez créer des remplacements à temps.

Conseils de sécurité

  • Utilisez un jeton distinct pour chaque service ou outil
  • Choisissez des noms descriptifs pour identifier clairement les jetons
  • Ne stockez jamais les jetons en clair dans les systèmes de contrôle de version
  • Renouvelez les jetons régulièrement
  • Révoquez immédiatement les jetons en cas de suspicion d'abus

Chaque jeton est lié à votre compte utilisateur. Via MCP, il dispose des droits de votre compte, plafonnés au niveau superviseur : même si votre compte est administrateur, le jeton ne porte jamais de droits d'administrateur. Le mode d'accès limite en outre ce que l'agent peut faire : avec « Lecture seule », il n'utilise que des fonctions de lecture ; avec « Lecture et écriture », il effectue les modifications sans aucune confirmation supplémentaire. Traitez les jetons avec le même soin que votre mot de passe.
