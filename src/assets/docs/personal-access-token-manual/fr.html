Manuel des Personal Access Tokens

Que sont les Personal Access Tokens ?

Les Personal Access Tokens (PATs) sont des clés d'API durables qui permettent aux outils et services externes d'accéder à Klacks de manière sécurisée — sans nom d'utilisateur ni mot de passe.

Cas d'utilisation typiques :

  • MCP (Model Context Protocol) — permet aux assistants IA comme Claude Desktop d'accéder directement aux compétences Klacksy
  • Scripts d'automatisation et pipelines CI/CD
  • Outils de monitoring et d'intégration externes

Concept de sécurité

Klacks ne stocke jamais le token en clair. Après la création, seul un hachage SHA-256 du token est enregistré dans la base de données. Le token lui-même n'est affiché qu'une seule fois, immédiatement après sa création, et ne peut pas être récupéré ultérieurement.

Remarque : copiez ou notez votre token immédiatement après sa création. En cas de perte, vous devez créer un nouveau token et révoquer l'ancien.

Créer un token

Étape par étape

  • Accédez à Configuration → Personal Access Tokens
  • Cliquez sur Créer un nouveau token
  • Saisissez un nom explicite (p. ex. Claude Desktop ou Pipeline CI)
  • Sélectionnez la durée de validité souhaitée (1–730 jours, par défaut : 365 jours)
  • Cliquez sur Créer
  • Copiez immédiatement le token affiché — il n'est visible qu'une seule fois

Format du token

klacks_pat_<chaîne aléatoire>

Chaque token commence par le préfixe klacks_pat_ suivi d'une chaîne aléatoire cryptographiquement sécurisée.

Durées de validité

DuréeUtilisation recommandée
1–30 joursTests à court terme et développement
90–180 joursPipelines CI/CD avec rotation régulière
365 jours (par défaut)Intégrations permanentes (p. ex. Claude Desktop)
730 joursIntégrations système à long terme

Utiliser un token

Token Bearer dans l'en-tête HTTP

Le token est transmis en tant que Bearer token dans l'en-tête Authorization de chaque requête API :

Authorization: Bearer klacks_pat_...

Configurer MCP avec Claude Desktop

Le point de terminaison MCP (/mcp) donne aux assistants IA comme Claude Desktop un accès direct à toutes les compétences Klacksy — consulter les données des employés, planifier des équipes, gérer des groupes et bien plus encore.

Configuration dans l'application Claude Desktop (claude_desktop_config.json) :

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-fetch",
        "https://<votre-domaine-klacks>/mcp"
      ],
      "env": {
        "AUTHORIZATION": "Bearer klacks_pat_..."
      }
    }
  }
}

Remplacez <votre-domaine-klacks> par l'adresse de votre installation Klacks et klacks_pat_... par le token que vous avez créé.

Requête API directe (curl)

curl -H "Authorization: Bearer klacks_pat_..." \
     https://<votre-domaine-klacks>/api/clients

Gestion et sécurité

Vue d'ensemble des tokens

Sous Configuration → Personal Access Tokens, vous pouvez voir tous vos tokens avec leur nom, date de création, date d'expiration et dernière utilisation. Le token en clair n'est jamais affiché dans cette vue.

Révoquer un token

Un token peut être révoqué à tout moment. Après révocation, toutes les requêtes utilisant ce token sont immédiatement rejetées. Révoquez un token immédiatement lorsque :

  • Le token a été accidentellement partagé ou exposé
  • Un appareil ou service n'est plus utilisé
  • Vous remarquez une activité suspecte

Expiration

Les tokens expirés sont automatiquement rejetés. Klacks met en évidence dans la vue d'ensemble les tokens qui expirent dans les 30 prochains jours afin que vous puissiez créer des remplacements à temps.

Conseils de sécurité

  • Utilisez un token distinct pour chaque service ou outil
  • Choisissez des noms descriptifs pour identifier clairement les tokens
  • Ne stockez jamais les tokens en clair dans les systèmes de contrôle de version
  • Renouvelez les tokens régulièrement, en particulier pour les pipelines CI/CD
  • Révoquez immédiatement les tokens en cas de suspicion d'abus

Chaque token est lié à votre compte utilisateur et dispose des mêmes droits que votre compte. Traitez les tokens avec le même soin que votre mot de passe.
