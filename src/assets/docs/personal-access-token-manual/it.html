Manuale dei Personal Access Token

Cosa sono i Personal Access Token?

I Personal Access Token (PAT) sono chiavi API di lunga durata che consentono a strumenti e servizi esterni di accedere a Klacks in modo sicuro — senza nome utente e password.

Casi d'uso tipici:

  • MCP (Model Context Protocol) — consente agli assistenti IA come Claude Desktop di accedere direttamente alle competenze di Klacksy
  • Agenti e assistenti IA che lavorano con Klacks tramite MCP

Concetto di sicurezza

Klacks non memorizza mai il token in chiaro. Dopo la creazione, nel database viene salvato esclusivamente un hash SHA-256 del token. Il token stesso viene visualizzato solo una volta, immediatamente dopo la creazione, e non può essere recuperato in seguito.

Nota: copiare o annotare il token immediatamente dopo la creazione. In caso di smarrimento è necessario creare un nuovo token e revocare quello precedente.

Creare un token

Passo dopo passo

  • Accedere a Configurazione → Personal Access Token
  • Fare clic su Crea nuovo token
  • Inserire un nome descrittivo (ad es. Claude Desktop o Agente IA pianificazione)
  • Selezionare la durata di validità desiderata (1–730 giorni, predefinito: 365 giorni)
  • Fare clic su Crea
  • Copiare immediatamente il token visualizzato — viene mostrato una sola volta

Formato del token

klacks_pat_<stringa casuale>

Ogni token inizia con il prefisso klacks_pat_ seguito da una stringa casuale crittograficamente sicura.

Durate di validità

DurataUtilizzo consigliato
1–30 giorniTest a breve termine e sviluppo
90–180 giorniAgenti IA con rotazione regolare
365 giorni (predefinito)Integrazioni permanenti (ad es. Claude Desktop)
730 giorniIntegrazioni di sistema a lungo termine

Modalità di accesso

Durante la creazione si stabilisce che cosa un agente esterno può fare con il token:

  • Sola lettura (predefinita) — l’agente vede e usa esclusivamente strumenti di lettura. Ogni tentativo di modificare i dati viene rifiutato.
  • Lettura e scrittura — l’agente può anche modificare i dati senza che una persona approvi ogni singola modifica. Scegliere questa modalità solo per agenti a cui si affidano modifiche.

La modalità è indicata nell’elenco dei token e non può essere cambiata in seguito; se necessario creare un nuovo token. I token già esistenti e quelli emessi tramite un accesso OAuth (ad es. un connettore MCP) hanno la modalità «Lettura e scrittura».

Utilizzare un token

Bearer token nell'intestazione HTTP

Il token viene trasmesso come Bearer token nell'intestazione Authorization di ogni richiesta MCP all'endpoint /mcp:

Authorization: Bearer klacks_pat_...

Configurare MCP con Claude Desktop

L'endpoint MCP (/mcp) consente agli assistenti IA come Claude Desktop di accedere direttamente a tutte le competenze Klacksy — consultare i dati dei dipendenti, pianificare i turni, gestire i gruppi e molto altro.

Configurazione nell'applicazione Claude Desktop (claude_desktop_config.json):

{
  "mcpServers": {
    "klacks": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://<dominio-klacks>/mcp",
        "--header",
        "Authorization:${AUTH_HEADER}"
      ],
      "env": {
        "AUTH_HEADER": "Bearer klacks_pat_..."
      }
    }
  }
}

Sostituire <dominio-klacks> con l'indirizzo della propria installazione Klacks e klacks_pat_... con il token creato.

Nota: I token valgono solo per l'accesso MCP degli agenti IA (endpoint /mcp). L'API REST di Klacks (ad es. /api/clients) non li accetta; richiede il token di accesso (login).

Gestione e sicurezza

Panoramica dei token

Sotto Configurazione → Personal Access Token sono visibili tutti i token con nome, data di creazione, data di scadenza e ultimo utilizzo. Il token in chiaro non viene mai visualizzato in questa schermata.

Revocare un token

Un token può essere revocato in qualsiasi momento. Dopo la revoca, tutte le richieste che utilizzano quel token vengono immediatamente rifiutate. Revocare un token immediatamente quando:

  • Il token è stato condiviso o esposto accidentalmente
  • Un dispositivo o servizio non è più in uso
  • Si notano attività sospette

Scadenza

I token scaduti vengono rifiutati automaticamente. Klacks evidenzia nella panoramica i token che scadono entro i prossimi 30 giorni in modo da poter creare token sostitutivi in tempo.

Suggerimenti per la sicurezza

  • Utilizzare un token separato per ogni servizio o strumento
  • Scegliere nomi descrittivi per identificare chiaramente i token
  • Non memorizzare mai i token in chiaro nei sistemi di controllo versione
  • Ruotare i token regolarmente
  • Revocare immediatamente i token in caso di sospetto utilizzo improprio

Ogni token è associato al proprio account utente. Tramite MCP dispone delle autorizzazioni dell'account, ma limitate al livello di supervisore: anche se l'account è amministratore, il token non possiede mai diritti di amministratore. La modalità di accesso limita inoltre ciò che l'agente può fare: con «Sola lettura» utilizza solo funzioni di lettura; con «Lettura e scrittura» esegue le modifiche senza ulteriore conferma. Trattare i token con la stessa cura della propria password.
