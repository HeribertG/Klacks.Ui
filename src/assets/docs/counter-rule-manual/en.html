Counter Rules – Manual

What are counter rules?

Counter rules count recurring events per person over a defined period and trigger a warning or a block in the schedule when a threshold is exceeded. They are used to enforce operational or legal limits, such as the maximum number of night shifts per month.

The settings in detail

Event type

Determines which event is counted:

  • Night shift – counts shifts that fall into the defined night window.
  • Worked day per week – counts the days per week on which the person is scheduled.
  • Shift exceeding hours – counts shifts whose duration exceeds the hours threshold defined below.

Period

The window over which counting happens: week, month or year. The counter resets at the start of each new period.

Threshold

The maximum permitted number of the event within the period. Once the value is reached or exceeded, enforcement applies. Example: threshold 5 with event type night shift and period month limits the person to five night shifts per month.

Hours threshold

Only relevant and only shown when the event type shift exceeding hours is selected. Defines from which shift duration (in hours) a shift is counted as an event.

Enforcement

How the schedule reacts when the threshold is exceeded:

  • Inherit default – uses the default mode configured under compliance enforcement.
  • Warn – shows a notice but still allows scheduling.
  • Block – prevents scheduling until the rule is satisfied again.

Scheduling rule binding (optional)

Links the counter rule to an existing scheduling rule. Left empty, the counter rule applies on its own. The binding is optional and not needed for standard cases.

Important note on imported rules

  • Rules that originate from a region setup (country profile) are restored when the region setup is re-imported. Deleting such a row is therefore not permanent – it reappears after the next re-import.
  • A scheduling rule binding set on an imported row is reset to its original value on re-import. Manually created rules are not affected.
