ERP Order Import – Manual

What is the ERP order import?

External ERP systems deliver orders to Klacks as XML files. There are three transfer channels:

  • Drop point (pull): The ERP places the files in the drop point's file store – depending on the installation a directory on the Klacks server (default) or an S3-compatible object storage. Klacks collects the files automatically according to the configured schedule.
  • Direct upload (push): The ERP sends the file via HTTP POST to /api/erp-import/upload, authenticating with an ERP import token as a bearer token. Each file may be at most 50 MB.
  • Manual upload: Administrators drag XML files into the drop zone directly on this page (or click the zone to select a file). After the upload the import is triggered automatically and starts within a minute; the Import now button triggers it again at any time.

Drop point

The drop point is the central mailbox for all import files. Klacks manages it automatically – nobody has to create or configure it. The page shows its content as a import list with three areas: Inbox (received or currently being imported, with progress), Processed (with a summary per file) and Errors (unreadable or invalid files and interrupted imports including the reason). Failed files can be imported once more via the Import again button.

  • Enabled switch (import active) – pauses the automatic import; files already delivered are kept.
  • Status display – time of the last poll and, if present, the last error.

Access tokens

  • Administrators can create access tokens for push delivery — only needed if an external ERP system delivers files via HTTPS. Every token starts with the prefix klacks_erp_.
  • The validity period is configurable (1 to 730 days, default 365 days).
  • The token plaintext is shown only once, at creation. It cannot be retrieved afterwards – copy it immediately and store it securely.
  • An ERP import token is deliberately valid for the import endpoint only. If a token leaks at the ERP vendor, no other API access to Klacks is possible with it.
  • Tokens can be revoked at any time; access ends immediately.

Schedule

Polling of the drop point follows a cron expression (default 0 * * * * = hourly) in the selected time zone. Both are configured on this page. An invalid cron expression would stop the import – the input is therefore validated and invalid values are not saved.

XML format (reference)

The root element is ErpOrderImport with the required attributes schemaVersion (currently 1) and sourceSystemId. The sourceSystemId identifies the delivering system in the files and provides the stable customer matching across all deliveries – it must stay constant for each source system. Each order lives in its own <Order> element. A file may contain any number of orders.

Element Required Format Meaning
ExternalOrderReference Yes Text Unique order reference of the ERP system.
Description No Text Free text for the order (e.g. assignment notes); shown on the order.
Customer Yes Element Customer data of the order (see child elements).
Customer/ExternalCustomerReference No (recommended) Text External customer reference; guarantees stable customer matching across imports.
Customer/Company Yes Text Company name of the customer.
Customer/Address/Street Yes Text Street and house number.
Customer/Address/Zip Yes Text Postal code.
Customer/Address/City, Customer/Address/State, Customer/Address/Country No Text City, state/region and country.
FromDate Yes yyyy-MM-dd Start of the order.
UntilDate No yyyy-MM-dd End of the order; missing or empty = open-ended.
StartTime, EndTime Yes HH:mm Start and end time of the assignment.
IsTimeRange No true/false (default false) true = time window in which work takes place; false = fixed shift from StartTime to EndTime. When true, Duration is required.
Duration When IsTimeRange=true Element with <Hours> and <Minutes> (integers) Duration of the single assignment, e.g. 0 h 20 min for a 20-minute visit within the 08:00–15:00 window. Optional for fixed shifts; if missing, the duration from StartTime to EndTime applies.
Quantity No Integer (default 1) Number of assignments.
SumEmployees No Integer (default 1) Number of employees required.
Weekdays Yes Attributes monday … sunday, each true/false Weekdays of the order; at least one weekday must be true, a missing attribute counts as false. Orders without a weekday are rejected.

Note: Element names are case-sensitive. A complete sample file is available via the Download sample file button above this manual.

Customer matching

Klacks assigns every order to a customer:

  • First via the combination of source system ID and external customer reference – once matched, this reference permanently resolves to the same customer.
  • Without an external reference, the first occurrence is matched via company + postal code + street; casing and whitespace are ignored.
  • If no match is found, Klacks creates the customer automatically.

Processing & lifecycle

  • Imported orders are created as drafts and must be reviewed and sealed by planners or administrators. During review the planner also adds any required qualifications — the ERP can pass them along as a hint in the Description field.
  • If the ERP later delivers a changed version of an already sealed order, Klacks automatically closes the old order by end date and creates a new, linked draft version. Already planned future, unlocked assignments of the old order are removed and the planners are notified.
  • Unchanged repeat deliveries (e.g. a nightly full export) trigger nothing.

Error handling & archive

  • The original file stays in the drop point folder (for audit and retries; it is not moved, and there are no sub-folders). Its status is shown on the import page: while it is imported in the Inbox area (with progress), then in the Processed area with a summary (new, updated, unchanged, superseded and rejected orders), together with who delivered it and how (upload, ERP push or folder). A file identical to an earlier delivery only shows an info hint and is imported anyway.
  • Unreadable files (e.g. broken XML), files that were changed after receipt and interrupted imports appear in the Errors area with the reason; from there they can be imported once more via Import again or deleted. A corrected file has to be uploaded anew. Successfully processed files (Processed area) are deleted automatically after 90 days; files in the Errors area stay until they are imported again via Import again or deleted.
  • Incomplete or invalid orders are rejected (for example without a weekday, with UntilDate before FromDate, or with a duplicate ExternalOrderReference within the same file); the remaining orders of the same file are still imported.
  • A file with at least one rejected order still appears in the Processed area, marked with a warning icon: the valid orders are imported and the rejected ones can be expanded together with their reason.
  • Errors are logged and the administrators are notified.
