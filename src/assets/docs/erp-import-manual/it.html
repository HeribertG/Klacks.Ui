Importazione ordini ERP – Manuale

Cos'è l'importazione degli ordini ERP?

I sistemi ERP esterni consegnano gli ordini a Klacks come file XML. Sono disponibili tre canali di trasferimento:

  • Drop point (prelievo): l'ERP deposita i file nell'area di deposito del drop point – a seconda dell'installazione una directory sul server Klacks (impostazione predefinita) oppure un'archiviazione oggetti compatibile S3. Klacks preleva i file automaticamente secondo la pianificazione configurata.
  • Caricamento diretto (push): l'ERP invia il file tramite HTTP POST a /api/erp-import/upload, autenticandosi con un token di importazione ERP come token Bearer. Ogni file può avere al massimo 50 MB.
  • Caricamento manuale: gli amministratori trascinano i file XML direttamente nella zona di deposito di questa pagina (oppure fanno clic sulla zona per selezionare un file). Dopo il caricamento l'importazione viene avviata automaticamente e parte entro un minuto; il pulsante Importa ora la riavvia in qualsiasi momento.

Drop point

Il drop point è la cassetta postale centrale per tutti i file di importazione. Klacks lo gestisce automaticamente – nessuno deve crearlo o configurarlo. La pagina mostra il suo contenuto come vista dei file con tre aree: In arrivo (in attesa della prossima esecuzione di importazione), Elaborati (archivio) ed Errori (file illeggibili o non validi con il motivo dell'errore). I file in errore possono essere riportati in arrivo tramite il pulsante Reimporta.

  • Interruttore attivo (importazione attiva) – mette in pausa l'importazione automatica; i file già depositati vengono conservati.
  • Indicatore di stato – ora dell'ultima interrogazione e, se presente, l'ultimo errore.

Token di accesso

  • Gli amministratori possono creare token di accesso per la consegna in push — necessari solo se un sistema ERP esterno consegna i file tramite HTTPS. Ogni token inizia con il prefisso klacks_erp_.
  • La durata di validità è configurabile (da 1 a 730 giorni, 365 giorni per impostazione predefinita).
  • Il token in chiaro viene mostrato una sola volta, alla creazione. In seguito non è più recuperabile – va copiato subito e conservato in modo sicuro.
  • Un token di importazione ERP è deliberatamente valido solo per l'endpoint di importazione. In caso di fuga presso il fornitore ERP, con questo token non è possibile alcun altro accesso API a Klacks.
  • I token possono essere revocati in qualsiasi momento; l'accesso termina subito.

Pianificazione

Il prelievo dal drop point segue un'espressione cron (predefinita 0 * * * * = ogni ora) nel fuso orario selezionato. Entrambi si configurano in questa pagina. Un'espressione cron non valida fermerebbe l'importazione – l'immissione viene quindi validata e i valori non validi non vengono salvati.

Formato XML (riferimento)

L'elemento radice è ErpOrderImport con gli attributi obbligatori schemaVersion (attualmente 1) e sourceSystemId. Il sourceSystemId identifica il sistema che consegna nei file e garantisce l'assegnazione stabile dei clienti in tutte le consegne – deve rimanere costante per ogni sistema di origine. Ogni ordine si trova in un proprio elemento <Order>. Un file può contenere un numero qualsiasi di ordini.

Nota: i nomi degli elementi distinguono tra maiuscole e minuscole. Un file di esempio completo è disponibile tramite il pulsante Scarica il file di esempio sopra questo manuale.

Assegnazione dei clienti

Klacks assegna ogni ordine a un cliente:

  • Prima tramite la combinazione di ID del sistema di origine e riferimento cliente esterno – una volta assegnato, questo riferimento rimanda stabilmente allo stesso cliente.
  • Senza riferimento esterno, alla prima occorrenza la ricerca avviene tramite ragione sociale + codice postale + via; maiuscole/minuscole e spazi vengono ignorati.
  • Se non c'è alcuna corrispondenza, Klacks crea automaticamente il cliente.

Elaborazione & ciclo di vita

  • Gli ordini importati nascono come bozze e devono essere verificati e sigillati dai pianificatori o dagli amministratori. Durante la verifica il pianificatore aggiunge anche le qualifiche richieste — l'ERP può trasmetterle come indicazione nel campo Description.
  • Se l'ERP consegna in seguito una versione modificata di un ordine già sigillato, Klacks chiude automaticamente il vecchio ordine tramite data di fine e crea una nuova versione bozza collegata. Gli impieghi futuri già pianificati e non bloccati del vecchio ordine vengono rimossi e i pianificatori vengono avvisati.
  • Le consegne ripetute invariate (ad es. un'esportazione completa notturna) non attivano nulla.

Gestione degli errori & archivio

  • I file elaborati vengono spostati nella sottocartella processed/ dell'area di deposito (archivio, nessuna cancellazione); appaiono nella pagina di importazione nell'area Elaborati.
  • I file illeggibili o non validi vengono spostati nella sottocartella error/ e appaiono nell'area Errori; da lì possono essere riportati in arrivo tramite Reimporta.
  • Gli ordini incompleti o non validi vengono rifiutati (ad esempio senza giorno della settimana, con UntilDate precedente a FromDate o con una ExternalOrderReference duplicata nello stesso file); gli altri ordini dello stesso file vengono comunque importati.
  • Un file con almeno un ordine rifiutato passa nell'area Errore insieme al motivo del rifiuto — gli ordini già importati restano importati.
  • Gli errori vengono registrati e gli amministratori vengono avvisati.
