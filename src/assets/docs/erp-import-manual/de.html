ERP-Bestellungs-Import – Handbuch

Was ist der ERP-Bestellungs-Import?

Externe ERP-Systeme liefern Bestellungen als XML-Dateien an Klacks. Für die Übertragung gibt es drei Wege:

  • Drop-Point (Abholung): Das ERP legt die Dateien in der Dateiablage des Drop-Points ab – je nach Installation ein Verzeichnis auf dem Klacks-Server (Standard) oder ein S3-kompatibler Objektspeicher. Klacks holt die Dateien nach dem konfigurierten Zeitplan automatisch ab.
  • Direkter Upload (Push): Das ERP sendet die Datei per HTTP POST an /api/erp-import/upload und authentifiziert sich dabei mit einem ERP-Import-Token als Bearer-Token. Pro Datei sind maximal 50 MB erlaubt.
  • Manueller Upload: Administratoren ziehen XML-Dateien direkt auf dieser Seite in die Ablage-Zone (oder klicken die Zone an, um eine Datei auszuwählen). Nach dem Hochladen wird der Import automatisch angestossen und startet innerhalb einer Minute; der Button Jetzt importieren stösst ihn jederzeit zusätzlich an.

Drop-Point

Der Drop-Point ist der zentrale Briefkasten für alle Import-Dateien. Klacks verwaltet ihn automatisch – niemand muss ihn anlegen oder konfigurieren. Die Seite zeigt seinen Inhalt als Datei-Ansicht mit drei Bereichen: Eingang (wartet auf den nächsten Import-Lauf), Verarbeitet (Archiv) und Fehler (nicht lesbare oder ungültige Dateien samt Fehlergrund). Fehler-Dateien lassen sich über den Button Erneut importieren zurück in den Eingang verschieben.

  • Aktiv-Schalter (Import aktiv) – pausiert den automatischen Import; bereits abgelegte Dateien bleiben erhalten.
  • Statusanzeige – letzter Abrufzeitpunkt und, falls vorhanden, der letzte Fehler.

Zugriffstoken

  • Für die Push-Anlieferung können Administratoren Zugriffstoken erstellen — nötig nur, wenn ein externes ERP-System Dateien per HTTPS anliefert. Jedes Token beginnt mit dem Präfix klacks_erp_.
  • Die Gültigkeitsdauer ist wählbar (1 bis 730 Tage, Standard 365 Tage).
  • Der Token-Klartext wird nur einmal bei der Erstellung angezeigt. Danach ist er nicht mehr abrufbar – sofort kopieren und sicher hinterlegen.
  • Ein ERP-Import-Token ist bewusst nur für den Import-Endpoint gültig. Gerät ein Token beim ERP-Dienstleister in falsche Hände, ist damit kein anderer API-Zugriff auf Klacks möglich.
  • Tokens können jederzeit widerrufen werden; der Zugriff endet sofort.

Zeitplan

Der Abruf des Drop-Points folgt einem Cron-Ausdruck (Standard 0 * * * * = stündlich) in der gewählten Zeitzone. Beides wird auf dieser Seite konfiguriert. Ein ungültiger Cron-Ausdruck würde den Import stoppen – die Eingabe wird deshalb validiert und ungültige Werte werden nicht gespeichert.

XML-Format (Referenz)

Wurzelelement ist ErpOrderImport mit den Pflicht-Attributen schemaVersion (aktuell 1) und sourceSystemId. Die sourceSystemId identifiziert das liefernde System in den Dateien und sorgt für die stabile Kunden-Zuordnung über alle Lieferungen – sie muss pro Quellsystem dauerhaft konstant bleiben. Jede Bestellung steht in einem eigenen <Order>-Element. Eine Datei darf beliebig viele Bestellungen enthalten.

Element Pflicht Format Bedeutung
ExternalOrderReference Ja Text Eindeutige Bestellreferenz des ERP-Systems.
Description Nein Text Freitext zur Bestellung (z. B. Einsatzhinweise); wird auf der Bestellung angezeigt.
Customer Ja Element Kundendaten der Bestellung (siehe Unterelemente).
Customer/ExternalCustomerReference Nein (empfohlen) Text Externe Kundenreferenz; sichert die stabile Kunden-Zuordnung über alle Importe.
Customer/Company Ja Text Firmenname des Kunden.
Customer/Address/Street Ja Text Strasse und Hausnummer.
Customer/Address/Zip Ja Text Postleitzahl.
Customer/Address/City, Customer/Address/State, Customer/Address/Country Nein Text Ort, Kanton/Region und Land.
FromDate Ja yyyy-MM-dd Beginn der Bestellung.
UntilDate Nein yyyy-MM-dd Ende der Bestellung; fehlend oder leer = unbefristet.
StartTime, EndTime Ja HH:mm Beginn- und Endzeit des Einsatzes.
IsTimeRange Nein true/false (Standard false) true = Zeitfenster, in dem gearbeitet wird; false = feste Schicht von StartTime bis EndTime. Bei true ist Duration Pflicht.
Duration Bei IsTimeRange=true Element mit <Hours> und <Minutes> (Ganzzahlen) Dauer des einzelnen Einsatzes, z. B. 0 h 20 min für einen 20-Minuten-Einsatz im Zeitfenster 08:00–15:00. Bei fester Schicht optional; fehlt das Element, gilt die Dauer von StartTime bis EndTime.
Quantity Nein Ganzzahl (Standard 1) Anzahl Einsätze.
SumEmployees Nein Ganzzahl (Standard 1) Anzahl benötigter Mitarbeitender.
Weekdays Ja Attribute monday … sunday, je true/false Wochentage der Bestellung; mindestens ein Wochentag muss true sein, ein fehlendes Attribut zählt als false. Bestellungen ohne Wochentag werden abgelehnt.

Hinweis: Die Element-Namen sind case-sensitiv. Eine vollständige Beispieldatei lässt sich über den Button Beispieldatei herunterladen oberhalb dieses Handbuchs beziehen.

Kunden-Zuordnung

Klacks ordnet jede Bestellung einem Kunden zu:

  • Zuerst über die Kombination aus Quellsystem-ID und externer Kundenreferenz – einmal zugeordnet, bleibt diese Referenz dauerhaft demselben Kunden zugewiesen.
  • Ohne externe Referenz wird beim ersten Auftreten über Firma + PLZ + Strasse gesucht; Gross-/Kleinschreibung und Leerzeichen werden dabei ignoriert.
  • Findet sich kein Treffer, legt Klacks den Kunden automatisch neu an.

Verarbeitung & Lebenszyklus

  • Importierte Bestellungen entstehen als Entwurf und müssen von Planern oder Administratoren geprüft und versiegelt werden. Dabei ergänzt der Planer auch allfällige Qualifikationsanforderungen — das ERP kann diese als Hinweis im Feld Description mitliefern.
  • Liefert das ERP später eine geänderte Version einer bereits versiegelten Bestellung, schliesst Klacks die alte Bestellung automatisch per Enddatum und legt eine neue, verknüpfte Entwurfs-Version an. Bereits geplante zukünftige, nicht gesperrte Einsätze der alten Bestellung werden entfernt und die Planer benachrichtigt.
  • Unveränderte Wiederholungslieferungen (z. B. ein nächtlicher Vollexport) lösen nichts aus.

Fehlerbehandlung & Archiv

  • Verarbeitete Dateien werden in der Dateiablage in den Unterordner processed/ verschoben (Archiv, keine Löschung); sie erscheinen auf der Import-Seite im Bereich Verarbeitet.
  • Nicht lesbare oder ungültige Dateien wandern in den Unterordner error/ und erscheinen im Bereich Fehler; von dort lassen sie sich per Erneut importieren zurück in den Eingang verschieben.
  • Unvollständige oder ungültige Bestellungen werden abgelehnt (z. B. ohne Wochentag, mit UntilDate vor FromDate oder mit doppelter ExternalOrderReference in derselben Datei); die übrigen Bestellungen derselben Datei werden trotzdem importiert.
  • Enthält eine Datei mindestens eine abgelehnte Bestellung, wandert sie mit dem Ablehnungsgrund in den Bereich Fehler — die bereits importierten Bestellungen bleiben dabei erhalten.
  • Fehler werden protokolliert und die Administratoren benachrichtigt.
